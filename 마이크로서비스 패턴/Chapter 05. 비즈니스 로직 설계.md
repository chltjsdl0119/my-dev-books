# Chapter 05. 비즈니스 로직 설계

- 클래스가 여러 서비스에 산재된 마이크로서비스 아키텍처에서는 서비스 경계를 넘나드는 객체 레퍼런스를 제거해야 한다.
- 마이크로서비스 아키텍처 특유의 트랜잭션 관리 제약 조건하에서도 작동되는 비즈니스 로직을 설계해야 한다.

- 애그리거트를 사용하면 객체 레퍼런스가 서비스 경계를 넘나들 일이 없다. 객체 참조 대신 기본키를 이용하여 애그리거트가 서로 참조하기 때문이다.

## 5.1 비즈니스 로직 구성 패턴

- 비즈니스 로직은 절차적 트랜잭션 스크립트 패턴과 객체지향적 도메인 모델 패턴. 두 가지 패턴으로 구성한다.

### 5.1.1 비즈니스 로직 설계: 트랜잭션 스크립트 패턴

- 트랜잭션 스크립트 패턴은 동작이 구현된 클래스와 상태를 보관하는 클래스가 따로 존재하는 중요한 특징이 있다.

### 5.1.2 비즈니스 로직 설계: 도메인 모델 패턴

- 비즈니스 로직을 상태와 동작을 가진 클래스로 구성된 객체 모델로 구성한다.
- 해당 패턴을 적용하면 서비스 메서드가 단순해진다.

### 5.1.3 도메인 주도 설계 개요

#### DDD에서 도메인 모델을 구축하는 데 쓰이는 빌딩 블록

- entity
- value object
- factory
- repository
- service

## 5.2 도메인 모델 설계: DDD 애그리거트 패턴

### 5.2.1 불분명한 경계 문제

- 도메인 객체의 경계가 분명하지 않으면 비즈니스 객체를 업데이트할 때 문제가 생길 수 있다.
